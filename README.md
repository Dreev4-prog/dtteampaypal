# DT Team PayPal Bot v2.5.19 — Editable Daily Auto Posts

## Автопосты в админке
Откройте «Админ-панель» → «📅 АВТОПОСТЫ». Этот же раздел есть в «START / STOP».

- Два начальных поста уже включены: **13:00 и 18:00 по Москве**. Используются одобренные первые баннеры «PayPal ждёт тебя» и «Продолжаем работу». Проценты и контакты не вписаны в картинки: текст пользователя сохранён отдельной подписью.
- Под каждым постом — кнопка **«💳 Получить PayPal»**, открывающая обычную заявку с действующими проверками доступа и START WORK.
- В карточке можно изменить время, название для админки, текст и фото, включить/выключить пост или удалить его с подтверждением.
- «Добавить пост» последовательно запрашивает название, время, текст и фото (можно без картинки), показывает личный предпросмотр и сохраняет после «Сохранить и включить».
- Предпросмотр получает только администратор, который нажал кнопку. Он доступен и при STOP WORK; запуск рассылки участникам эта кнопка не делает.
- Название видно только администраторам. Подпись — обычный текст с переносами строк и эмодзи, до 1024 символов Telegram. HTML-теги вводить не нужно. Проценты в подписи сохранены как введённый текст: при изменении тарифов отредактируйте подписи постов.
- Список постов листается по 10 записей, без общего ограничения количества. Новый пост создаёт дополнительную ежедневную отправку, так что после добавления постов их может быть больше двух за день.

## Когда выполняется отправка
- В назначенную минуту по Москве бот проверяет START WORK. При STOP WORK пост пропускается. Если включили START WORK уже после назначенного времени, пропущенный пост не отправляется вдогонку.
- Новое время или включение поста применяется к будущим отправкам. Пост, который уже запускался сегодня, повторно в этот московский день не отправится, даже после изменения времени. Следующий запуск — по новому расписанию в следующий день.
- Внутренний планировщик работает вместе с ботом и проверяет расписание каждые 10 секунд. Внешний cron не нужен. Если бот не работал всю назначенную минуту, отправка пропускается.
- Рассылка идёт всем одобренным участникам. Заблокированные, отклонённые и ожидающие одобрения не получают автопосты. Статус участника проверяется ещё раз непосредственно перед отправкой.
- START WORK и актуальность поста проверяются перед каждой отправкой. STOP WORK, выключение, изменение или удаление поста прекращает оставшуюся рассылку старого содержимого. Уже доставленные и находящиеся в отправке сообщения отозвать нельзя.
- Если несколько постов назначены близко по времени, медленная рассылка одного не блокирует отслеживание остальных. У них общий ограничитель скорости отправки.

## Перезапуск, повторы и ошибки
- Начало запуска записывается в базе до обращения к Telegram. Один пост запускается не более одного раза за московский день; повторное нажатие «Сохранить» не создаёт дубликат поста.
- При перезапуске начатая рассылка автоматически не продолжается и не повторяется: это предотвращает дубли при неизвестном результате доставки. Часть адресатов при прерывании может не получить пост. Следующая попытка — по расписанию в следующий день.
- Явное ограничение Telegram с коротким сроком ожидания повторяется один раз после паузы и новой проверки START WORK. Сетевые ошибки с неизвестным результатом доставки автоматически не повторяются.
- В карточке показаны последний запуск, количество доставленных сообщений, ошибки и причина пропуска/остановки. После аварийного завершения процесса статус может остаться «Начат; завершение не подтверждено».
- Посты, время, тексты, картинки, выключение и удаление сохраняются в базе. Перезапуск не восстанавливает удалённые начальные посты и не заменяет внесённые правки.

## Установка
Замените файлы из архива и перезапустите бот. Новые таблицы `auto_posts` и `auto_post_runs` создаются при запуске. После обновления два начальных поста готовы к ближайшему будущему времени, если START WORK включён. Сам факт передачи архива не обновляет работающий бот.

Все предыдущие исправления истории PayPal, Gestop / GeS, возвратов, ожидания вывода и центра выплат включены.

Проверка: `pip install -r requirements-dev.txt`, затем `python -m unittest discover -s tests -v`. Проверки выполняются на отдельной SQLite-базе и имитации Telegram. Блокировки PostgreSQL, доставка в рабочем Telegram и рабочее расписание на сервере здесь не проверялись.


# DT Team PayPal Bot v2.5.18 — Withdrawal Hold and Notifications

## Подтверждение оплаты и вывод с PayPal
- Подтверждение поступления денег фиксирует процент и начисление, но оставляет его в ожидании вывода с PayPal. Сумма пока не входит в доступный баланс, центр выплат, итоги CryptoBot / xRocket и общий чек.
- В «Работа с PayPal» → «💸 Вывести с PayPal» находятся подтверждённые оплаты без назначенного ожидания. После фактического вывода нажмите «✅ Сделано — деньги выведены»: только тогда начисление станет доступным к выплате.
- Если вывести не удалось, нажмите «⏳ Ждём 24 часа». Заявка перейдёт в отдельный раздел с оставшимся временем, датой следующей попытки и счётчиком ожиданий. В списке первыми показаны ближайшие и уже наступившие сроки; список листается без общего ограничения числа заявок.
- Через 24 часа карточка показывает, что пора повторить попытку. Деньги остаются в ожидании до успешного вывода. После неудачной повторной попытки можно нажать «⏳ Ещё 24 часа».
- Время и номер периода ожидания сохраняются в базе. Перезапуск их не сбрасывает, повторное нажатие старой кнопки не продлевает срок. Обратный отсчёт обновляется при открытии или нажатии «Обновить». Даты показаны по московскому времени.
- Вывод и повторная попытка выполняются администратором вручную. По наступлении срока бот не делает перевод и не начисляет доступный баланс автоматически.
- После отметки об успешном выводе заявка доступна в «💰 Готовы к выплате» и центре выплат.

## Что видит пользователь
1. После подтверждения поступления — «✅ Оплата подтверждена», PayPal, полученная сумма, процент и начисление в USDT. Указано, что начисление ожидает вывода с PayPal.
2. После «Ждём 24 часа» — «⏳ Вывод с PayPal отложен»: сейчас вывести не удалось, ждём 24 часа; показаны дата следующей попытки и начисление в ожидании. Новый период ожидания отправляет новое уведомление; повтор старой кнопки его не дублирует.
3. После «Деньги выведены» — «💸 Средства успешно выведены с PayPal»: на сколько USDT пополнен баланс к выплате, сколько доступно всего и выбранный способ — CryptoBot или xRocket.

В кошельке и «Мои PayPal» доступный баланс и ожидание показаны отдельно. Есть раздел «Ожидают вывода с PayPal» с датами и обновлением. GeS остаётся виден только администрации. При ошибке Telegram администратор видит предупреждение о неподтверждённой доставке уведомления; сохранённое состояние платежа не отменяется. Автоматической повторной отправки уведомлений нет.

## Возвраты и защита выплат
- «Оплата возвращена — отменить начисление» работает как для ожидания, так и для уже доступного, но ещё не выплаченного начисления. Запись о платеже сохраняется.
- Сумма и зафиксированное начисление после подтверждения не редактируются. Изменение тарифов во время ожидания не меняет уже рассчитанное начисление, в том числе Happy Hours.
- Повторная отметка успешного вывода не начисляет деньги дважды. Старые кнопки индивидуальной выплаты также проверяют факт вывода и обновляют общий учёт баланса.
- Если состав доступных начислений изменился после подготовки общего чека, например после вывода ещё одного PayPal, чек не отправляется: нужно открыть выплату заново с актуальной суммой.

## Обновление существующего бота
- При запуске добавляются `withdrawal_retry_at` и `withdrawal_wait_count`. Старые невыплаченные начисления без отметки вывода с PayPal автоматически переводятся из доступных в ожидание. Для них не назначается выдуманный срок 24 часа; сначала проверьте фактический вывод и выберите действие в карточке.
- Уже выплаченные, отменённые и отмеченные как выведенные платежи этим переносом не меняются. Ранее заданные сроки ожидания сохраняются. Миграция не рассылает старым пользователям уведомления задним числом.
- Замените файлы из архива и перезапустите бот. Все исправления v2.5.13–v2.5.17 включены. Передача архива сама по себе не обновляет работающий бот.

Проверка: `pip install -r requirements-dev.txt`, затем `python -m unittest discover -s tests -v`. Тесты используют отдельную SQLite-базу и имитацию Telegram. Проверяются три уведомления, повторные нажатия, ожидание и его истечение, 200 записей, перенос старых начислений, возвраты и исключение ожидания из выплат. Блокировки PostgreSQL и доставка через рабочий Telegram здесь не проверялись.


# DT Team PayPal Bot v2.5.17 — Confirmed Payment Return

## Вернули уже подтверждённую оплату
- Откройте «Работа с PayPal» → «Вывести деньги» → нужную заявку → «↩️ Оплата возвращена — отменить начисление».
- Перед подтверждением показаны номер заявки, PayPal, пользователь, сумма оплаты и точная сумма отменяемого начисления в USDT.
- Действие предназначено для полного возврата уже полученной оплаты, пока начисление пользователю ещё не выплачено. Сам возврат денег выполняется вручную через PayPal; бот фиксирует его результат.
- Подтверждение убирает только это начисление из доступного баланса, центра выплат и очереди «Вывести деньги». Суммы CryptoBot / xRocket пересчитываются при обновлении экрана. Другие начисления пользователя сохраняются.
- История остаётся: в разделе «Платежи» есть «Возвращённые оплаты», в карточке видны дата и администратор. Пользователь видит запись в «Мои PayPal» → «Закрытые / проблемные» с пометкой об отмене начисления.
- Возвращённая оплата исключается из успешных платежей DT Payments, рейтинга, финансовых итогов и оборота Happy Hours. Факт первоначального подтверждения и сумма начисления сохраняются для истории.
- Статус самого PayPal и его отметка GeS не меняются.

## Защита при отмене и выплате
- Повторное подтверждение возврата не списывает баланс второй раз. Начисление с уже проведённой выплатой отменять этой кнопкой нельзя.
- Отмена начисления и запись о возврате сохраняются одной транзакцией. Отмена и общая выплата блокируют данные в одинаковом порядке.
- При подготовке общего чека запоминаются начисления и способ выплаты. Если они изменились, например после отмены оплаты, старый чек не пересылается пользователю: нужно заново открыть выплату и подготовить чек на актуальную сумму.
- Проверка начислений, отправка чека и фиксация выплаты выполняются под общей блокировкой с отменой. При ошибке отправки изменения базы откатываются. Ошибка Telegram/соединения может иметь неопределённый результат доставки; перед повтором нужно проверить доставку чека и историю выплат.

## Обновление
- При запуске автоматически добавляются поля `payment_refunded_at` и `payment_refunded_by`. Рабочие записи не удаляются.
- Замените файлы из архива и перезапустите бот. После этого уже существующую подтверждённую заявку можно отменить новой кнопкой.
- Предыдущие исправления истории, центра выплат и Gestop / GeS включены.

Проверка: `pip install -r requirements-dev.txt`, затем `python -m unittest discover -s tests -v`. Тесты используют отдельную SQLite-базу и имитацию Telegram, без рабочих выплат. Блокировки PostgreSQL и рабочий Telegram требуют проверки в окружении развёртывания.

- Если PayPal вручную освободили ещё до появления учёта Gestop и в базе не осталось ни даты, ни связанных записей, восстановить этот факт невозможно. Для текущих Gestop без даты признак сохраняется.
